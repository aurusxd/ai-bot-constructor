# CLAUDE.md

Источник правды по проекту — `tech.md` в корне репозитория. Прочитай его перед
любой задачей и следуй ему дословно: стек, схема БД, эндпоинты API, структура
папок, логика бота, конвенция коммитов.

Правила:

- Не выдумывай поля, таблицы, эндпоинты или названия, которых нет в `tech.md`.
- Если для задачи не хватает контракта (поля, эндпоинта, таблицы) — не изобретай
  его молча. Допиши недостающее прямо в `tech.md` (раздел, к которому оно
  относится), затем реализуй код на основе дополненного файла. Один разработчик
  на проекте, версии и changelog можно не вести отдельно, но `tech.md` должен
  оставаться актуальным описанием того, что реализовано.
- Работай по одной задаче за раз из раздела «Дорожная карта» в `tech.md`, не
  реализуй сразу всё приложение целиком.
- Миграции пиши через Alembic, не правь схему БД в обход миграции.
- Коммиты и комментарии — по конвенции из раздела 10 `tech.md`.
- После реализации задачи сверься с Definition of Done (раздел 11 `tech.md`).
